# FE-Act 작업 지시문 - 메시지/에러 피드백 반영

다음 작업은 `fe-act`에게 전달한다.
수정 범위는 `frontend/**`로 제한한다.
문서와 원본 설계 문서는 수정하지 않는다.

## 작업 목적
실서비스 기준의 메시지/에러 피드백 정책을 프론트에 반영한다.
개발용 정보 노출, 전면 에러 남용, 메시지 노출 방식 불일치를 정리한다.

## 반드시 반영할 것

### 1. Auth 화면
- 로그인 실패, 회원가입 일반 실패, rate limit, 네트워크 실패를 전면 `ErrorState`로 띄우지 말 것
- 위 케이스는 모두 폼 상단 인라인 알림으로 통일할 것
- 필드 오류는 계속 필드 하단 인라인 에러로 유지할 것
- 사용자에게 `백엔드`, `API`, `localhost`, 상태 코드, 내부 설계 용어를 보여주지 말 것
- 로그인/회원가입 성공 후 오래 머무는 성공 카드가 꼭 필요하지 않다면 다음 흐름 전환을 우선할 것

### 2. silent refresh 실패 / 인증 만료
- 보호 라우트 접근 시 refresh 실패하면 로그인 화면으로 보내되, 사용자는 `로그인이 만료되었어요` 수준의 안내를 인지할 수 있어야 함
- 노출 방식은 로그인 화면 상단 배너 또는 차단형 안내 카드 중 하나로 통일할 것
- 문구에는 `이 기기의 기록은 그대로 유지됩니다`를 포함할 것

### 3. bootstrap 레이어
- 로그인/회원가입 성공 직후 대시보드로 바로 보내지 말고, `SCR-09-A` 정책을 반영할 수 있는 구조를 만들 것
- 최소 범위:
  - 로딩 레이어
  - 네트워크 실패 레이어
  - 충돌 레이어를 구분 가능한 상태 구조
- 이번 라운드에서 실제 bootstrap API를 붙이지 못하더라도 UI 상태 구조와 카피는 정책에 맞출 것

### 4. 설정 화면
- 로그아웃 실패는 세션 관리 섹션 내부 인라인 알림으로 노출할 것
- 성공/실패 메시지는 사용자 행동 중심 문구로 바꿀 것
- 이후 동기화/설정 저장에 재사용 가능한 success toast 진입점도 고려할 것

### 5. 공통 메시지 정책
- 공통 기본 네트워크 실패 문구:
  - `지금은 연결이 원활하지 않아요. 잠시 후 다시 시도해 주세요.`
- CTA 문구는 행동형으로 통일할 것
  - `다시 시도`
  - `다시 로그인`
  - `계속하기`
  - `최신 상태 반영 후 계속`
- 같은 종류의 오류가 화면마다 다른 톤으로 분산되지 않게 정리할 것

## 구현 우선순위
1. Auth 인라인 알림 구조 정리
2. 인증 만료 배너/카드 추가
3. bootstrap 레이어 UI 상태 구조 추가
4. Settings 인라인 오류/성공 피드백 정리
5. 공통 메시지 상수 또는 메시지 사전 분리

## 검증 기준
- `npm run lint`
- `npm run typecheck`
- `npm run build`
- 브라우저에서 더 이상 개발용 인프라 문구가 직접 노출되지 않을 것
- Auth/Settings에서 에러가 전체 화면 카드로 과도하게 확장되지 않을 것
