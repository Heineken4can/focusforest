## 1. 공통 규칙

### 1.1 문서 목적
- 화면을 시각 시안보다 먼저 텍스트로 정의한다.
- 각 화면의 정보 구조, 사용자 행동, 상태 변화를 빠르게 합의한다.
- HTML/컴포넌트 작업 전, PO/FE/BE가 같은 구조를 보고 이야기할 수 있게 한다.

### 1.2 공통 레이아웃 원칙
- 모바일: 단일 컬럼 중심
- 태블릿: 단일 컬럼 유지, 좌측 메뉴 축약 가능
- 데스크톱: 좌측 메뉴 + 메인 콘텐츠 + 필요 시 우측 보조 영역
- 집중 모드: 불필요한 UI 제거, 메인 타이머 중심
- 인증/설정: 카드 또는 모달/바텀시트 중심

### 1.3 공통 네비게이션 원칙
- 상단 바: 현재 화면 제목, 보조 액션(프로필/뒤로가기/닫기)
- 좌측 메뉴: 데스크톱에서만 사용, 홈/집중/프로필(설정 포함) 중심
- 하단 메뉴: 모바일에서 홈/집중/프로필 중심
- 집중 모드 중에는 편집 액션 금지, 조회 전용만 허용

### 1.4 공통 상태 원칙
- Empty: 데이터 없음 안내 + 다음 행동 CTA
- Loading: 화면 전환 시 1초 이내 검은색 Dimmed 페이드를 기본 연출로 사용하고, 데이터 초기 로드 시에는 skeleton 또는 간단한 로더를 사용한다.
- Disabled: 클릭 불가 이유가 명확해야 함
- Error: 인증 만료, 동기화 충돌, 네트워크 실패 시 현재 데이터 보존 여부와 다음 행동(재시도/로그인/최신 상태 반영)을 함께 노출
- Success: 완료/보상/저장 성공을 짧고 명확하게 안내

### 1.5 공통 데이터 원칙
- 비로그인 상태: localStorage/IndexedDB 기준
- 로그인 상태: 서버 동기화 기준
- 타이머 초 단위 계산: 클라이언트 로컬 기준
- 보상/SP/레벨 정산: 서버 기준
- 인증 정보는 평문 저장 금지 원칙을 따른다.

### 1.6 공통 언어 원칙
- UI 기본 언어는 한국어로 사용한다.
- 집중 화면(SCR-04, SCR-05, SCR-07)은 몰입 연출 목적에 한해 제한적인 영문 혼용을 허용한다.
- 영문 혼용 시에도 핵심 행동 버튼과 오류/상태 안내는 한국어 우선으로 유지한다.

| SCR-02 | 대시보드 - 기본 | 오늘 할 일과 핵심 과제 확인 |

| SCR-06 | 집중 모드 - 포기 경고 | 포기 전 재확인 |
| SCR-07 | 집중 모드 - 휴식 | 5분 휴식 또는 Skip |
| SCR-08 | 완료 및 보상 | 나무/100 SP 획득 안내 |
| SCR-09 | 회원가입 및 로그인 | 계정 생성, 로그인, 로컬 모드 진입 |

### 2.1 보조 화면/레이어 정의
- `SCR-02-A`: 과제 생성 입력 레이어
- `SCR-02-B`: 과제 수정 입력 레이어
- `SCR-02-C`: 과제 삭제 확인 다이얼로그
- `SCR-09-A`: bootstrap 동기화 로딩/충돌 레이어
- 위 보조 레이어는 메인 화면 수(`SCR-01 ~ SCR-10`)에는 포함하지 않지만, 구현과 QA 대상 화면 정의로 관리한다.

## 3. SCR-01 대시보드 - Empty State

### 화면 목적
- 오늘 할 일이 없을 때 사용자가 막히지 않도록 첫 행동을 안내한다.

### 진입 조건
- 최초 진입
- 오늘 할 일이 0개인 상태
- 모든 과제가 제거된 직후

### 레이아웃 구조
- 상단 영역: 페이지 제목, 프로필 버튼
- 좌측 메뉴: 데스크톱에서 홈/집중/프로필
- 메인 영역: 빈 상태 안내 카드
- 하단 영역: 모바일 하단 메뉴

### 네비게이션
- 상단 제목: 홈
- 좌측 메뉴: 홈, 집중, 프로필
- 하단 메뉴: 홈, 집중, 프로필

### 주요 섹션
- Empty 안내 문구
- 첫 과제 추가 CTA
- 집중 시작 비활성 CTA

### 구성요소 상세
- Empty 카드:
  - 역할: 현재 상태 설명
  - 표시 데이터: 안내 문구, 설명, CTA
  - 가능한 액션: 첫 과제 추가
  - 상태: 기본
- 집중 시작 버튼:
  - 역할: 다음 단계 예고
  - 상태: 비활성

### 인터랙션 / 상태 변화
- 과제 추가 클릭 시 `SCR-02-A 과제 생성 입력 레이어`를 연다. 모바일은 `bottom sheet`, 데스크톱은 `max-w-md` 센터 모달을 사용한다.
- `SCR-02-A`에는 `과제명(필수)`과 `보조 설명(optional)`을 배치한다.
- 저장 성공 시 입력 레이어를 닫고 첫 과제를 목록 상단에 반영한다.
- 첫 과제가 생성되면 SCR-02로 전환한다.

### 반응형 메모
- 모바일: 카드 1개만 중앙 배치
- 데스크톱: 넓은 여백과 중앙 정렬 유지

### 접근성 메모
- Empty 상태는 시각 정보 외 텍스트 설명 필수
- 비활성 버튼은 이유가 문구로 함께 보여야 함

### 연동 데이터
- task count
- 사용자 로그인 여부
- local mode flag

## 4. SCR-02 대시보드 - 기본

### 화면 목적
- 사용자가 오늘의 할 일, 현재 핵심 과제, 오늘의 통계를 한 화면에서 확인하도록 한다.

### 진입 조건
- 오늘 할 일이 1개 이상 존재
- 집중 모드가 아닌 일반 홈 상태

### 레이아웃 구조
- 상단 영역: 제목, 검색/프로필
- 좌측 메뉴: 홈, 집중, 프로필
- 중앙 메인 영역: 히어로, 할 일 목록, 통계
- 우측 보조 영역: 데스크톱에서 선택적 요약 정보
- 하단 영역: 모바일 하단 메뉴

### 네비게이션
- 상단 탭 메뉴: 전체 / 진행중 / 완료 필터 기본 제공
- V1 필터 기준은 과제 상태 3종으로 고정하고, 카테고리/우선순위 필터는 후속 범위에서 다룬다.
- 좌측 메뉴: 홈, 집중, 프로필
- 하단 메뉴: 홈, 집중, 프로필

### 주요 섹션
- 히어로 영역: 현재 핵심 과제, 오늘 누적 집중 정보, 집중 시작 CTA
- 리스트 영역: 오늘의 할 일 목록
- 통계 영역: 오늘 집중 시간, 완료 세션 수, 누적 SP, 오늘의 나무, 현재 레벨
- 보조 액션 영역: 과제 추가, 필터, 정렬
- 보조 플로우 영역: `SCR-02-A 과제 생성`, `SCR-02-B 과제 수정`, `SCR-02-C 과제 삭제 확인` 레이어

### 구성요소 상세
- 히어로 카드:
  - 역할: 가장 중요한 행동 강조
  - 표시 데이터: 핵심 과제명, 최근 몰입 정보, CTA
  - 가능한 액션: 집중 시작
- 할 일 리스트:
  - 역할: 오늘 과제 확인 및 선택
  - 표시 데이터: 과제명, 상태, 보조 설명
  - 가능한 액션: 선택, 수정, 삭제
  - 상태: 기본, hover, selected, 완료, 잠금, 삭제 대기
- `SCR-02-A` 과제 생성 입력 레이어:
  - 역할: 새 과제를 즉시 등록
  - 패턴: 모바일 `bottom sheet`, 데스크톱 `max-w-md` 센터 모달
  - 필드: `과제명(필수)`, `보조 설명(optional)`
  - 가능한 액션: 저장, 닫기
  - 상태: 기본, validation error, saving
- `SCR-02-B` 과제 수정 입력 레이어:
  - 역할: 기존 과제의 제목/보조 설명 수정
  - 패턴: `SCR-02-A`와 동일
  - 가능한 액션: 저장, 취소
  - 상태: 기본, validation error, saving
- `SCR-02-C` 과제 삭제 확인 다이얼로그:
  - 역할: 삭제 전 최종 확인
  - 안내 문구: 과제를 삭제해도 과거 집중 기록과 이미 획득한 보상은 유지된다.
  - 가능한 액션: 삭제, 취소
  - 상태: 기본, deleting
- 통계 카드:
  - 역할: 오늘 성과 요약
  - 표시 데이터: 오늘 집중 시간, 완료 세션 수, 누적 SP, 오늘의 나무, 현재 레벨

### 인터랙션 / 상태 변화
- 리스트 항목 선택 시 SCR-03 상태로 전환 가능
- 과제 추가 클릭 시 `SCR-02-A`를 열고, 저장 성공 시 현재 필터 기준 목록과 히어로 요약을 즉시 갱신한다.
- 수정 클릭 시 `SCR-02-B`를 열고, 저장 성공 시 해당 row를 제자리 갱신한다.
- 삭제 클릭 시 `SCR-02-C`를 열고, 확정 시 row를 제거한다. 이때 과거 집중 기록과 보상 유지 안내를 함께 노출한다.
- 완료된 과제는 편집 가능하더라도 집중 시작 대상에서는 제외
- 진행 중 세션이 연결된 과제는 수정/삭제 잠금 상태로 유지하고, helper text로 잠금 이유를 설명한다.
- 자정 경계에 도달하거나 앱이 포그라운드로 복귀하면 선택된 타임존 기준으로 대시보드 요약을 다시 계산한다. 이때 `오늘의 나무`는 0으로 초기화되고, 누적 SP와 레벨은 유지된다.
- 자정 리셋 직후 첫 진입에서는 `오늘의 나무가 새로 시작되었어요` 수준의 짧은 helper text를 1회 노출할 수 있다.

### 반응형 메모
- 모바일: 단일 컬럼, 통계 영역은 하단 축약 가능
- 데스크톱: 히어로와 리스트 중심, 통계는 아래 또는 우측
- 생성/수정은 모바일에서 화면 하단에서 바로 이어지는 입력 경험을 우선한다.

### 접근성 메모
- 리스트 항목은 버튼 또는 링크 역할이 명확해야 함
- 아이콘 버튼은 aria-label 필요
- 삭제 확인 다이얼로그는 제목, 본문, 파괴적 액션이 스크린리더에 구분되게 전달되어야 함

### 마이크로 인터랙션 메모
- 리스트 row hover 시 `toss-surfaceHover` 배경을 사용한다.
- selected row는 `toss-selected` 배경과 좌측 포인트 라인으로 구분한다.
- 완료 처리된 row는 check 상태 전환 후 `line-through + opacity-40`로 잔잔하게 수렴시킨다.
- 삭제 확정 시 row는 짧은 slide-out 후 목록에서 제거한다.

### 연동 데이터
- task list
- selected task
- dashboard summary
- reward snapshot
- task create/edit draft
- delete target task
- day boundary status
- kpi event ids: `dashboard_task_set` (과제 생성 시)

## 5. SCR-03 과제 선택 뷰

### 화면 목적
- 사용자가 특정 과제를 핵심 과제로 지정한 뒤 집중 모드 진입 직전 상태를 확인한다.

### 진입 조건
- 대시보드에서 과제 1개 선택

### 레이아웃 구조
- 상단 영역: 홈 제목, 보조 액션
- 메인 영역: 선택된 핵심 과제 히어로, 선택된 리스트 row, 활성 CTA
- 하단 영역: 모바일 CTA 바

### 네비게이션
- 상단 바 유지
- 좌측 메뉴/하단 메뉴는 대시보드 규칙과 동일

### 주요 섹션
- 선택 완료 히어로
- 선택된 과제 행 강조
- 집중 시작 CTA

### 구성요소 상세
- 선택된 과제 카드:
  - 역할: 이번 세션 대상 강조
  - 표시 데이터: 과제명, 설명, 상태
  - 가능한 액션: 집중 시작
- 선택 row:
  - 역할: 목록 내부 선택 상태 표시
  - 상태: selected

### 인터랙션 / 상태 변화
- `집중 시작` 클릭 시 SCR-04로 이동
- 다른 과제를 선택하면 현재 핵심 과제가 교체됨

### 연동 데이터
- selected task id
- task status
- selected task isLocked
- selected task isCore
- kpi event ids: `dashboard_task_set` (핵심 과제 지정 시)

## 6. SCR-04 집중 모드 - 타이머 진행

### 화면 목적
- 사용자가 방해 없이 25분 집중 세션을 수행하도록 한다.

### 진입 조건
- 핵심 과제 선택 후 집중 시작

### 레이아웃 구조
- 상단 영역: 최소 정보 전용, 높이 64~80px 범위 유지
- 좌측 영역: 데스크톱 slim 메뉴 `w-20`, 태블릿/모바일 숨김 처리
- 중앙 메인 영역: `max-w-lg` 기준 단일 집중 셸, `px-6 lg:px-8` 내부 여백 유지
- 타이머 셸: 모바일 지름 280~320px, 데스크톱 최대 440px 범위 유지
- 우측 보조 영역: 데스크톱 전용 `w-80 px-6 py-8`, 다음 작업 후보 최대 2건 + 오늘 요약 노출
- 하단 영역: 모바일 fixed control bar `px-4 py-4`, 높이 80~88px

### 네비게이션
- 글로벌 네비게이션은 숨기거나 비활성화
- 데스크톱 우측 요약은 조회 전용
- 모바일 하단은 세션 컨트롤 전용
- 프로필/설정 진입 버튼은 이 화면에서 숨김 처리하여 SCR-10 접근을 차단한다.

### 주요 섹션
- 타이머 영역: 25분 카운트다운
- 과제 정보 영역: 현재 과제명, 보조 설명
- 컨트롤 영역: 포기, 일시정지
- 보조 요약 영역: 다음 작업 후보, 오늘 집중 현황 요약
- 전환 연출 영역: 진입/복귀 시 몰입 트랜지션

### 구성요소 상세
- 타이머:
  - 역할: 남은 시간 표시
  - 표시 데이터: mm:ss, 전체 세션 기준
  - 상태: `running`, `warning(남은 5분 이하)`, `completed` 직전 전환
  - 시각 규칙: 기본은 `toss-blue` Glow, warning 상태는 `toss-yellow` 포인트로 전환
- 세션 컨트롤:
  - 액션: 포기, 일시정지
  - 배치: 데스크톱 `max-w-xl` 수평 배치, 모바일 하단 고정 바
  - 규칙: Skip은 이 화면에서 노출하지 않음
  - 상태: Pause를 이미 1회 사용한 경우 일시정지 버튼 비활성 + 이유 문구 노출
- 우측 요약:
  - 역할: 다음 흐름 참고
  - 구성: 다음 작업 후보 2건, 오늘 완료 세션 수, 현재 핵심 과제 요약
  - 상태: read only
- 전환 연출:
  - 역할: 대시보드와 집중 화면 사이 몰입감 강화
  - 규칙: 진입 시 `bg-toss-overlay/60` + `toss-blue` Glow + 부드러운 페이드 적용
  - 규칙: 복귀 시 overlay 제거 + glow 강도 축소
  - 상태: 전환 중 1초 이내 검은색 Dimmed 로딩 페이드를 기본 연출로 적용

### 인터랙션 / 상태 변화
- 일시정지 클릭 시 SCR-05
- 포기 클릭 시 SCR-06
- 남은 시간이 5분 이하가 되면 타이머는 warning 상태로 전환된다.
- `visibilitychange` 이벤트를 통해 포그라운드 복귀를 감지하고, `Date.now()` 기준으로 잔여 시간을 재계산한다.
- 25분 완료 시 세션은 COMPLETED로 마감되고, SCR-08에서 보상 결과를 확인한 뒤 SCR-07 휴식으로 진입
- 완료 직후 보상 저장과 KPI 이벤트 발화 책임은 SCR-08에서 처리된다.

### 접근성 메모
- 타이머는 live region 필요
- 포기/일시정지 버튼은 키보드 접근 가능해야 함
- 전환 연출이 있더라도 핵심 버튼 포커스 이동은 즉시 인지 가능해야 함

### 연동 데이터
- active focus session
- remaining time
- current task
- next task candidates
- sidebar summary
- focusStartTimestamp
- pauseCount

## 7. SCR-05 집중 모드 - 일시정지 / 자동 취소 경고

### 화면 목적
- Pause 상태를 명확히 보여주고, 재개 또는 포기 결정을 빠르게 하게 한다.

### 진입 조건
- 집중 진행 중 Pause 선택 (세션 내 Pause 사용 횟수 0회인 경우에 한함)

### 레이아웃 구조
- SCR-04와 동일한 집중 레이아웃 유지
- 중앙 메인 영역은 `max-w-lg` 집중 셸 유지
- Pause 안내 배너는 타이머 상단 중앙 `max-w-md min-h-14` 인라인 배너로 고정
- 자동 포기 결과는 모바일/데스크톱 모두 하단 destructive toast로 노출

### 주요 섹션
- Pause 상태 배지
- 멈춘 타이머
- 다시 시작 / 포기 버튼
- 자동 취소 카운트다운 안내

### 구성요소 상세
- Pause 상태 배지:
  - 역할: 현재 세션이 일시정지 상태임을 즉시 전달
  - 표시 데이터: `Paused`, 남은 유예 시간
  - 시각 규칙: `toss-yellow` 포인트 사용
- Pause 안내 배너:
  - 역할: 남은 유예 시간과 제한 정책 설명
  - 표시 데이터: 남은 시간, `세션당 Pause 1회만 허용` 문구
  - 배치: 타이머 상단 인라인 배너
- 다시 시작 버튼:
  - 역할: 기존 세션으로 복귀
- 포기 버튼:
  - 역할: 세션 종료 선택
- 자동 포기 결과 토스트:
  - 역할: `보상 없음 / 대시보드 복귀` 결과를 짧게 알림
  - 위치: 모바일 `bottom-24`, 데스크톱 `bottom-8 center`

### 인터랙션 / 상태 변화
- Pause는 세션당 최대 1회만 허용한다.
- 다시 시작 클릭 시 SCR-04 복귀
- 포기 클릭 시 SCR-06
- 5분 초과 시 자동 포기 처리
- 자동 포기 처리 시 세션 무효화 + 보상 없음(나무 0, SP 0) 안내 메시지를 destructive toast로 4초 노출한 뒤 대시보드 복귀

### 연동 데이터
- pauseStartedAt
- pauseDeadlineAt
- pauseCount

## 8. SCR-06 집중 모드 - 포기 경고 모달

### 화면 목적
- 충동적인 중단을 한 번 더 확인하게 한다.

### 진입 조건
- 집중 중 `포기하기` 클릭
- Pause 상태에서 `포기하기` 클릭

### 레이아웃 구조
- 데스크톱: 센터 모달
- 모바일: 바텀시트

### 주요 섹션
- 경고 아이콘
- 포기 시 손실 안내 문구
- 계속 집중 / 포기 버튼

### 인터랙션 / 상태 변화
- 계속 집중: 진입 컨텍스트가 `RUNNING`이면 SCR-04로, `PAUSED`이면 SCR-05로 복귀
- 포기 확정: 세션 무효화 후 대시보드 복귀

### 접근성 메모
- 모달 열림 시 포커스 트랩 필요
- 닫기/확정 버튼 순서 명확해야 함

### 연동 데이터
- active session id
- warningContext

## 9. SCR-07 집중 모드 - 휴식(Break)

### 화면 목적
- 집중 세션 직후 5분 휴식을 제공하고, 사용자가 바로 다음 흐름을 결정하도록 한다.

### 진입 조건
- 25분 집중 세션 정상 완료 후 SCR-08 보상 확인 완료 시

### 레이아웃 구조
- 중앙 메인 영역: `max-w-md` 기준 단일 휴식 셸
- 하단 또는 버튼 영역: `max-w-sm` 범위 안에서 건너뛰기, 휴식 유지 배치
- 우측 보조 영역: 휴식 화면에서는 숨김 처리
- 배경 톤: `bg-toss-surface` 기반으로 전환하고, overlay 강도는 `bg-toss-overlay/20`로 완화

### 주요 섹션
- 휴식 상태 배지
- 5분 타이머
- 건너뛰기 CTA
- 휴식 유지 보조 CTA

### 구성요소 상세
- 휴식 상태 배지:
  - 역할: 집중 완료 후 휴식 단계 진입을 전달
  - 시각 규칙: `toss-green` 포인트 사용
- 5분 타이머:
  - 역할: 휴식 잔여 시간 표시
  - 시각 규칙: 집중 화면 대비 Glow 강도를 50% 수준으로 축소
- CTA 영역:
  - 배치: 데스크톱 가로 2버튼, 모바일 세로 또는 하단 고정 바 허용

### 인터랙션 / 상태 변화
- 건너뛰기 클릭 시 `BREAK_SKIPPED`로 종료되고 다음 집중 세션 준비 상태로 즉시 이행한다. 다음 작업 후보가 있으면 SCR-03, 없으면 SCR-02로 이동한다.
- 휴식 유지 시 5분 후 `BREAK_COMPLETED`로 종료되고 다음 집중 세션 준비 상태로 이동한다. 다음 작업 후보가 있으면 SCR-03, 없으면 SCR-02로 이동한다.
- 보상은 이미 지급된 상태로 유지

### 접근성 메모
- 건너뛰기 버튼은 키보드 접근 가능해야 함
- 휴식 종료 상태 변화는 스크린리더가 인지할 수 있는 텍스트로 전달되어야 함

### 연동 데이터
- break session state
- break remaining time
- next task candidates

## 10. SCR-08 완료 및 보상 화면

### 화면 목적
- 사용자가 집중 완료 보상을 명확히 인지하도록 한다.

### 진입 조건
- 25분 집중 세션 완료 직후

### 레이아웃 구조
- 데스크톱: `max-w-md` 기준 센터 모달
- 모바일: 바텀시트 단일 패턴으로 확정, 최대 높이 `85vh` 이내
- 상단 강조 영역: 보상 아이콘 + 레벨업 배지(조건부)
- 하단 영역: 확인 CTA, 저장/동기화 상태

### 주요 섹션
- 축하 아이콘 및 시각 강조 요소
- `나무 1그루 + 100 SP` 메시지
- 레벨업 배지 또는 레벨 상승 안내 문구
- 확인 CTA
- 저장/동기화 중이면 로딩 상태 추가

### 구성요소 상세
- 보상 강조 아이콘:
  - 기본 아이콘: `forest`
  - 시각 규칙: `toss-green` 계열 강조 사용
- 레벨업 배지:
  - 조건: 레벨업 조건 충족 시에만 노출
  - 아이콘: `military_tech`
  - 노출 방식: 별도 오버레이가 아니라 동일 모달/바텀시트 내부 확장 상태로 노출
- 확인 CTA:
  - 역할: 휴식 화면으로 다음 단계 진행
- 저장 상태:
  - 역할: 보상 저장/동기화 중 CTA 비활성 및 로딩 표시

### 인터랙션 / 상태 변화
- 확인 클릭 시 SCR-07 휴식 화면으로 진행
- SP 획득 후 `Floor(누적 SP / 1000) + 1` 기준으로 레벨업 조건 충족 시, 동일 모달 내부에서 레벨업 배지와 문구가 추가 노출된다.
- 저장 중에는 CTA 비활성

### 접근성 메모
- 성공 메시지는 짧고 명확한 텍스트 필요
- 로딩 시 aria-busy 고려

### 연동 데이터
- reward result
- updated stats snapshot
- sync status
- level up status
- kpi event ids: `focus_session_completed`, `reward_granted_first_time` (로그인 사용자 기준, `auth_signup_success` 이후 첫 보상 획득 시에 한해 발화)

## 11. SCR-09 회원가입 및 로그인

### 화면 목적
- 사용자가 계정을 생성하거나 로그인하고, 필요 시 로컬 모드로 계속 진행할 수 있게 한다.

### 진입 조건
- 앱 첫 진입
- 인증 만료
- 설정에서 로그아웃 후 재진입

### 레이아웃 구조
- 상단 영역: 화면 제목, 선택적 닫기 버튼
- 중앙 영역: `max-w-md` 기준 로그인/회원가입 공용 폼 카드
- 카드 상단: segmented tab(`로그인 / 회원가입`) 배치
- 하단 영역: 로컬 모드 진입 버튼, 로딩 예시

### 주요 섹션
- 로그인/회원가입 segmented tab
- 로그인 폼
- 로컬 모드 안내 문구
- 로그인 없이 시작하기 버튼
- `SCR-09-A` bootstrap 동기화 상태 레이어

### 구성요소 상세
- segmented tab:
  - 역할: 로그인 / 회원가입 화면 전환
  - 배치: 동일 카드 상단 `rounded-full` 탭 스위처
- 이메일 필드
- 비밀번호 필드
- 로그인 CTA
- 회원가입 CTA
- 로컬 모드 CTA
- 로컬 준비중 상태 버튼
- `SCR-09-A` bootstrap 동기화 로딩 레이어:
  - 역할: 로그인/회원가입 성공 직후 로컬 데이터 마이그레이션과 초기 동기화 진행 상황을 차단형으로 안내
  - 패턴: 모바일/데스크톱 모두 전체 카드 위 overlay 또는 full-screen blocking state 허용
  - 표시 데이터: 동기화 진행 문구, 로컬 데이터 보존 안내, 재시도 상태
- `SCR-09-A` bootstrap 충돌/오류 레이어:
  - 역할: 첫 로그인 동기화 중 충돌 또는 네트워크 실패 안내
  - 표시 데이터: 현재 로컬 데이터 보존 여부, 최신 상태 반영 안내, 다음 행동 CTA
  - 가능한 액션: 네트워크 실패 시 재시도, 충돌 시 최신 상태 반영 후 계속

### 인터랙션 / 상태 변화
- 로그인/회원가입 탭 전환은 동일 카드 안에서 `150ms ease-out` 기준 `opacity + translateX(8px)` 전환을 사용한다.
- 로그인 또는 회원가입 성공 직후에는 즉시 대시보드로 보내지 않고, `SCR-09-A` bootstrap 동기화 로딩 레이어를 먼저 노출한다.
- bootstrap 동기화가 성공하면 `activeSession`이 있으면 세션 상태 기준으로 SCR-04/SCR-05/SCR-07로 복귀하고, 없으면 task count에 따라 SCR-01 또는 SCR-02로 진입한다.
- bootstrap 중 네트워크 실패가 발생하면 현재 로컬 데이터 보존 안내와 함께 재시도 CTA를 노출한다.
- bootstrap 중 충돌이 발생하면 `SCR-09-A` 충돌/오류 레이어를 열고 `최신 상태 반영 후 계속`만 제공한다. `재시도`는 네트워크 실패일 때만 제공한다.
- 회원가입 후 자동 로그인 가능
- 로컬 모드 선택 시 task count에 따라 SCR-01 또는 SCR-02로 진입
- 인증 실패 시 토스트가 아니라 필드 하단 인라인 에러 메시지로 노출한다.
- 인증 만료 시 현재 로컬 데이터 보존 안내와 함께 재로그인 CTA를 노출

### 접근성 메모
- label/input 연결 필수
- 에러 메시지는 aria-describedby 연결
- bootstrap 로딩 상태와 충돌 상태는 제목/본문/다음 행동 CTA가 스크린리더에 순서대로 전달되어야 함

### 보안 메모
- 비밀번호 필드는 `type=password`를 기본값으로 사용한다.
- 비밀번호 표시/숨김 토글 제공 시 aria-label을 명확히 제공한다.
- 로그인, 회원가입, 동기화는 HTTPS 전송을 전제로 동작한다.

### 연동 데이터
- auth credentials
- local mode flag
- bootstrap pending status
- bootstrap sync result
- sync conflict notice
- task count
- kpi event ids: `app_first_open` (최초 진입 또는 신규 설치 후 첫 앱 구동 시에 한해 발화), `auth_signup_success`, `auth_login_success`

## 12. SCR-10 프로필 및 환경설정

### 화면 목적
- 사용자가 프로필 상태를 확인하고 테마, 타임존, 동기화, 저장 기준을 조정하거나 확인하게 한다.

### 진입 조건
- 프로필 버튼 클릭
- 로그인 상태에서 설정 진입
- 로컬 모드에서 프로필/설정 진입

### 레이아웃 구조
- 데스크톱: 모달
- 모바일: 바텀시트
- 상단 영역: 프로필 요약
- 설정 영역: 토글, 셀, 버튼 목록

### 주요 섹션
- 프로필 요약: 이메일, 레벨, 누적 SP, 오늘의 나무
- 설정 섹션:
  - 테마 설정
  - 타임존 설정
  - 자동 동기화 설정
  - 로컬 모드/계정 상태 안내
  - 동기화 충돌 / 네트워크 오류 안내
- 액션 섹션:
  - 수동 동기화
  - 로그아웃

### 구성요소 상세
- 프로필 카드:
  - 표시 데이터: 이메일, 레벨, 누적 SP, 오늘의 나무, 연결 상태
  - 메모: 레벨 계산 기준은 `Floor(누적 SP / 1000) + 1`
- 테마 설정:
  - 옵션: 시스템 / 라이트 / 다크
- 타임존 설정:
  - 옵션: 사용자 선택 또는 시스템 기본값
  - 역할: 오늘의 나무/날짜 집계 기준
- 자동 동기화 스위치:
  - 역할: 동기화 정책 확인 및 제어
- 로컬 모드/계정 상태:
  - 역할: 현재 저장 기준(로컬 전용/계정 동기화)을 안내
- 오류 안내 영역:
  - 역할: 동기화 충돌, 네트워크 실패 시 데이터 보존 여부와 다음 행동을 설명
  - 표시 데이터: 현재 로컬 데이터 보존 여부, 서버 최신 상태 반영 안내, 재시도 가능 여부
- 수동 동기화 버튼:
  - 역할: 즉시 bootstrap/push/pull 트리거
- 로그아웃 버튼:
  - 역할: 현재 세션 종료

### 인터랙션 / 상태 변화
- 테마 변경 시 즉시 UI 반영
- 타임존 변경 시 과거 일자를 소급 재집계하지 않고, 이후 완료 세션부터 새 집계 기준에 반영
- 자동 동기화 변경 시 이후 동기화 정책에 반영
- 수동 동기화 실행 시 로딩 상태 표시
- 설정 저장 완료 또는 수동 동기화 성공 시 success toast를 3.5초 노출한다.
- 동기화 충돌 시 현재 데이터 보존 여부와 서버 최신 상태 반영 CTA를 함께 안내하며, 오류 성격상 inline alert를 우선 사용한다.
- 네트워크 실패 시 재시도 CTA와 오프라인 유지 안내를 함께 노출
- 로그아웃 시 인증 화면으로 이동

### 접근성 메모
- switch는 role=switch 필요
- 설정 항목 라벨은 텍스트로 명확해야 함
- 충돌/네트워크 오류 안내는 스크린리더가 이해할 수 있는 상태 텍스트를 포함해야 함

### 연동 데이터
- profile
- user settings
- theme
- timezone
- sync status
- local mode flag
- kpi event ids: 없음 (직접 발화하는 KPI 이벤트 없음, 로그아웃 후 SCR-09 재진입 시에도 `app_first_open`은 SCR-09의 최초 진입 조건을 만족하는 경우에만 발화)

## 13. 추천 사용 순서

1. 이 문서에서 먼저 화면 구조를 확정합니다.
2. 확정된 내용을 `ui_design.md`에 요약 반영합니다.
3. 필요한 화면만 `ui_reference_design_*.html`로 시안화합니다.
4. 마지막에 `design_system.md` 토큰과 연결합니다.

이 문서는 구조 합의용 정본으로 쓰고, 시각 상세는 뒤 단계에서 붙이는 방식을 권장합니다.
