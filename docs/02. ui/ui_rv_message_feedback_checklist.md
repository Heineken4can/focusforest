# UI-RV 체크리스트 - 메시지/에러 피드백

검수 대상: Auth, bootstrap 레이어, Settings, 공통 토스트/인라인 알림
참조 문서:
- `docs/02. ui/ui_text_definition.md`
- `docs/02. ui/ui_design.md`

정본 기준:
- 메시지/에러 피드백 정책의 단일 정본은 `docs/02. ui/ui_text_definition.md`이다.

---

## 1. 메시지 노출 방식
- [ ] 입력값 자체 오류는 필드 하단 인라인 에러로 노출되는가
- [ ] 로그인 실패/회원가입 실패/네트워크 실패가 전면 에러 카드가 아니라 폼 상단 인라인 알림으로 처리되는가
- [ ] 로그아웃 실패/동기화 실패가 해당 섹션 안에서 해결 가능한 인라인 알림으로 노출되는가
- [ ] bootstrap 진행/충돌/필수 재로그인처럼 차단이 필요한 상태만 레이어 또는 모달을 사용하는가
- [ ] 읽고 지나가면 되는 성공 피드백은 토스트로 처리되는가

## 2. 카피 품질
- [ ] 사용자 화면에 `백엔드`, `API`, `localhost`, 상태코드, `csrf`, `refresh token` 같은 내부 용어가 노출되지 않는가
- [ ] 사용자 화면에 `placeholder`, `read only`, `skeleton`, `SCR-xx` 같은 설계 용어가 남아 있지 않은가
- [ ] 모든 오류 메시지가 `무슨 일 -> 무엇을 하면 되는지` 순서로 작성되었는가
- [ ] 문장이 2문장 이내로 유지되는가
- [ ] 사용자 탓처럼 읽히는 표현이 없는가

## 3. Auth 검수 포인트
- [ ] 로그인 실패 문구가 `이메일 또는 비밀번호를 다시 확인해 주세요.` 수준으로 단순하고 직접적인가
- [ ] Auth rate limit 문구가 재시도 타이밍을 분명하게 안내하는가
- [ ] Auth 네트워크 실패 시 URL이나 환경 정보가 보이지 않는가
- [ ] 로그인/회원가입 성공 직후 피드백이 지나치게 길거나 설명적이지 않은가
- [ ] `로그인 없이 시작하기` 안내가 기술 개념 설명이 아니라 사용자 행동 중심인가

## 4. 인증 만료 / bootstrap 검수 포인트
- [ ] silent refresh 실패 시 사용자가 로그인 만료를 이해할 수 있는가
- [ ] 인증 만료 안내에 `기기의 기록은 유지된다`는 안심 정보가 포함되는가
- [ ] bootstrap 로딩, 네트워크 실패, 충돌이 서로 다른 메시지와 CTA를 가지는가
- [ ] 충돌 상태에서 `재시도`와 `최신 상태 반영`이 혼동되지 않는가

## 5. Settings 검수 포인트
- [ ] 로그아웃 실패가 페이지 전체 에러처럼 보이지 않고 세션 관리 영역 안에서 처리되는가
- [ ] 설정 저장/동기화 성공 토스트가 짧고 명확한가
- [ ] 동기화 실패/충돌 시 데이터 보존 여부와 다음 행동이 함께 안내되는가

## 6. 접근성
- [ ] 필드 에러가 `aria-describedby`로 연결되는가
- [ ] 인라인 alert가 `role="alert"` 또는 `aria-live`를 사용해 보조기기에 전달되는가
- [ ] 차단형 레이어에서 제목 -> 본문 -> CTA 순서가 스크린리더에 자연스럽게 전달되는가
- [ ] 토스트에 상태 텍스트가 포함되어 있는가

## 7. 종합 판정 기준
- CRITICAL:
  - 개발용 인프라 정보 노출
  - 전면 에러 남용으로 핵심 흐름 차단
  - 인증 만료/충돌 안내 부재
- WARN:
  - 문구 톤 불일치
  - CTA 문구 불통일
  - 성공/실패 노출 방식 혼재
- PASS:
  - 노출 방식, 카피, 접근성이 모두 정책과 일치
