## 1. Overview (목적 및 기대 효과)

### 1.1 문제 정의 (Problem Definition)
- **Pain Point**: 사용자들은 수많은 알림과 멀티태스킹 환경 속에서 한 가지 업무나 과제에 **깊이 몰입(Deep Work)**하는데 어려움을 겪고 있다. 방대한 할 일 목록만으로는 우선순위를 정해 실행하기 어렵고, 집중력 저하로 인한 스트레스가 누적된다.

### 1.2 제품 목표 및 핵심 가치 (Objective & Core Value)
- **단일 목표에 대한 몰입**: 한 번에 하나의 '핵심 작업'만 선택하게 하여, 선택된 작업 진행 시 다른 방해 요소를 시각적/기능적으로 차단하는 '집중 모드(Focus Mode)'를 제공한다.
- **감성적 게이미피케이션**: 집중을 성공적으로 마쳤을 때 시각적으로 '나무'가 자라나는 보상을 주어(Focus Forest), 딱딱한 시간 관리를 부드럽고 긍정적인 경험으로 전환한다. 또한 **씨앗 포인트(SP)**와 **레벨 시스템(숲지기)**을 통해 장기적인 동기를 부여한다.
- **경험 컨셉 (Theme)**:
  - **테마(Light/Dark) 자율 선택**: 사용자의 취향과 환경에 따라 라이트 모드(화사한 파스텔 톤)와 다크 모드(딥 블루/네온 포인트)를 자유롭게 선택할 수 있으며, 시스템 설정에 연동하거나 수동 조작이 가능하다.
  - **집중 모드 전환 연출 (Immersion)**: 집중 모드 진입 시 전체 컬러 모드(라이트/다크)가 강제로 뒤바뀌지는 않으나, 네비게이션 등 불필요한 UI 요소를 화면에서 숨기고(절제), 타이머 주변에 집중감을 주는 시각적 효과(Dimmed 처리, 글로우 이펙트 등)를 연출하여 긴장감과 몰입감을 유도한다.

## 2. Success Metrics (KPI)
본 프로젝트 MVP의 핵심 가치(집중 습관화)를 측정하기 위한 지표입니다.

| 지표 유형 | 측정 지표 (Metrics) | 세부 설명 및 목표치 |
|---|---|---|
| **활성(Engagement)** | 일평균 완전 집중 세션 수 | 유저 1인당 하루 평균 **성공적으로 완료한 타이머 세션(예: 25분)이 3회 이상** 발생하는가. |
| **리텐션(Retention)** | 7일 재방문율 (D7 Retention) | `auth_login_success`를 완료한 유저를 코호트로 삼아, 첫 로그인 후 7일 차에 대시보드에 재방문한 뒤 과제를 생성하거나 핵심 과제를 다시 지정한 비율 **40% 이상**. |
| **보상 경험(Reward)**| 첫 보상 획득률 | `auth_signup_success` 이후 3일 이내에 최초 1회의 집중 세션을 완료하여 보상(나무/SP)을 획득한 유저 비율 **70% 달성**. |

### 2.1 KPI 계측 기준

아래 이벤트는 V1 KPI 측정을 위한 최소 계측 단위로 정의합니다.

| 이벤트 | 발생 시점 | 활용 지표 |
|---|---|---|
| `app_first_open` | 최초 진입 또는 신규 설치 후 첫 앱 구동 시 | 익명 퍼널 및 설치/첫 실행 분석 |
| `auth_signup_success` | 회원가입 성공 시 | 가입 전환 모수 |
| `auth_login_success` | 로그인 성공 및 대시보드 진입 시 | D7 Retention 코호트 기준점 |
| `dashboard_task_set` | 로그인 후 대시보드에서 과제를 생성하거나 핵심 과제를 지정한 시점 | D7 Retention 최종 판정 |
| `focus_session_completed` | 25분 집중 세션이 정상 완료된 시점 | 일평균 완전 집중 세션 수 |
| `reward_granted_first_time` | 유저가 첫 나무/SP 보상을 획득한 시점 | 첫 보상 획득률 |

- `app_first_open`은 비로그인 상태에서도 익명 기기 기준으로 수집 가능해야 하며, 이후 로그인 전환 시 사용자 식별자와 선택적으로 연결될 수 있어야 한다.
- KPI 계측은 제품 요구사항이며, 구현 방식은 특정 채널로 고정하지 않는다. V1에서는 백엔드 이벤트 수집 API, 클라이언트 analytics SDK, 또는 동등한 계측 수단 중 하나 이상으로 위 이벤트를 안정적으로 수집할 수 있으면 된다.
- KPI 이벤트는 운영 로그와 별도로, 코호트 분석과 재집계가 가능한 형태로 보존 또는 조회 가능해야 한다.
- D7 Retention의 코호트 기준점은 `app_first_open`이 아니라 `auth_login_success`로 정의한다. 7일 차 재방문 행동은 `dashboard_task_set`으로 판정하며, `app_first_open`은 비로그인 유입 퍼널과 설치/첫 실행 분석을 위한 보조 이벤트로 사용한다.
- 오프라인 상태에서 발생한 KPI 이벤트는 로컬 큐에 임시 저장한 뒤 온라인 복귀 시 재전송할 수 있어야 하며, 비로그인 익명 이벤트와 로그인 이후 사용자 이벤트를 연결할 수 있는 최소 식별 규칙이 필요하다.
- `reward_granted_first_time`은 `auth_signup_success` 이후 최초로 지급된 보상을 기준으로 판정한다. 익명 상태에서 먼저 획득한 로컬 보상은 가입 후 첫 보상 획득률에 소급 반영하지 않는다.

| ID | User Story | Edge Case / 예외 처리 | 우선순위 |
|---|---|---|---|
| **US-1** | **As a** 유저, **I want** 오늘 해야 할 과제(Task)들을 등록, 필터링 및 조회하기를, **So that** 수행해야 할 전체 목록을 한눈에 파악할 수 있다. | 할 일이 0개일 경우, Empty State 렌더링. | Must |

### 3.2 핵심 비즈니스 로직 및 정책

#### 1) 뽀모도로(Pomodoro) 세션 기반 타이머 정책
- **기본 설정**: V1의 1개 뽀모도로 사이클은 **25분 집중 세션 + 5분 휴식 세션**으로 구성한다. (V1 하드코딩)
- **세션 단위 정의**: 본 문서의 KPI/보상/통계에서 말하는 `집중 세션 완료`는 휴식까지 포함한 30분 묶음이 아니라, **25분 집중 세션이 `00:00`에 도달하여 정상 종료된 상태**를 의미한다.
- **성장 (보상) 조건**: 25분 집중 세션 타이머가 `00:00`에 도달하여 정상적으로 자동 종료되었을 때만 나무 1그루와 SP 지급 로그를 기록한다.
- **포기 (Penalty)**: 유저가 24분 59초에 [포기하기]를 누르더라도 해당 세션의 집중 시간은 0으로 날아가고 보상도 취소된다.
- **일시정지(Pause) 및 휴식 건너뛰기(Skip) 규칙**:
  - `Pause`: 집중 모드 중 최대 1회, 5분까지만 일시정지가 가능하다. 이를 넘기면 세션은 즉시 '포기' 처리된다.
  - `Skip`: 휴식 세션에 한해서만 카운트다운을 종료하고 다음 세션으로 즉각 이행하는 용도로 사용된다.
  - 휴식 세션을 건너뛰더라도 이미 완료된 25분 집중 세션의 보상은 취소되지 않는다.

#### 2) 보상 및 계정(레벨) 정책 - SP(Seed Point)와 숲지기
- **SP (씨앗 포인트)**: 온전한 25분 집중 세션 1회를 완수할 때마다 **기본 100 SP**를 지급 거행.
- **레벨업**: 유저 누적 SP를 척도로 레벨이 자동 승급 (`Level = Floor(누적 SP / 1000) + 1`).
  - 예시: 0~999 SP(LV.1), 1000~1999 SP(LV.2), 23000 SP(LV.24).
- **V1 SP 소비처**: 단순 누적 및 레벨 뷰포인트로만 사용되며, V1엔 추가 상점 소비처는 구현 대상에서 제외.
- **V1 통계 범위**: 보상 관련 사용자 노출 통계는 `오늘의 나무`, `누적 SP`, `현재 레벨`까지를 기본 범위로 정의하며, `연속 달성일수(streak)`는 V1 범위에 포함하지 않는다.

#### 3) 과제(Task) 수정/삭제 정책
- 등록된 과제는 언제든 수정 및 삭제가 가능하나, **몰입(집중 모드)이 진행 중인 과제는 통계 및 데이터 무결성 보장을 위해 삭제 및 내용 수정이 불가능**하다. 수정/삭제를 원할 경우 반드시 진행 중인 세션을 [포기하기]로 중단한 후 대시보드에서 처리해야 한다.
- 과제를 삭제하더라도 과거에 완료된 집중 세션 기록, 나무/SP 보상, 집계 통계는 유지되어야 한다. 삭제는 현재 과제 목록에서의 노출 상태를 제거하는 의미로 해석한다.

#### 4) 데스크톱 사이드바 요약 정책
- V1 데스크톱 사이드바는 별도의 `Timeline` 도메인을 신설하지 않고, **오늘 완료한 집중 세션 수/현재 핵심 과제/다음 작업 후보**를 요약 조회하는 보조 영역으로 정의한다.
- 다음 작업 후보는 아직 완료되지 않은 과제 목록 중 사용자가 직전에 선택한 핵심 과제 또는 최신 수정 과제를 우선 노출하는 수준으로 시작한다.
- 집중 모드에서는 사이드바가 **조회 전용(Read Only)**으로 동작하며, 과제 생성/교체/삭제 같은 편집 액션은 허용하지 않는다.

#### 5) 로그인 동기화 및 충돌 정책
- 최초 로그인 또는 계정 연결 시 로컬 저장소의 과제/집중 세션/보상 집계는 서버 계정으로 마이그레이션을 시도한다.
- 동기화 충돌이 발생하더라도 **과거 집중 세션 기록과 누적 보상 집계는 삭제보다 보존을 우선**하며, 필요한 경우 병합 후 보존을 기본 원칙으로 한다.
- 단, 동일한 집중 세션이 로컬과 서버에 중복 존재하는 경우에는 안정적인 세션 식별자 또는 동등한 판별 키를 기준으로 **1건으로 병합**해야 하며, 나무/SP/KPI는 중복 집계하지 않는다.
- 현재 과제(Task) 상태 충돌은 별도 규칙으로 처리한다. 동일 과제에 대한 로컬/서버 수정 충돌이 발생하면 최신 수정 시각 기준의 값을 대표 상태로 노출하되, 충돌 사실과 재검토 필요 여부를 사용자에게 안내할 수 있어야 한다.
- 동일 과제에 대해 한쪽은 삭제, 다른쪽은 수정한 경우에는 최신 변경 시각의 액션을 최종 상태로 반영한다. 삭제가 최종 상태인 경우 과제는 목록에서 제거되어야 하며, 수정이 최종 상태인 경우 과제는 복원된 최신 내용으로 노출되어야 한다.

## 4. 비기능 요구사항 (NFR - Non-Functional Requirements)
1. **사용성 / 디자인 전환 (UX/UI)**:
   - 메인 대시보드(안정감/준비) $\leftrightarrow$ 집중 모드(긴장감/타이머) 간 넘어가거나 복귀할 때, 포커스 특수 효과(UI Dimming, 블러, 글로우 등)를 적용하여 시각적 충격 없이 부드럽고 매끄러운 트랜지션(`transition-all` 등)을 선사해야 한다.
2. **타이머 성능 보장 (Reliability)**:
   - JS `setInterval` 백그라운드 지연 현상을 막고자, `visibilitychange` 이벤트 감지를 통해 로컬 Timestamp(`Date.now()`) 기반으로 타이머 잔여 시간을 재동기화해야 한다.
3. **글로벌라이제이션 (Language)**:
   - 한국어(Korean)를 메인 언어로 채택하되, 몰입 모드 UI 등 디자인적 시너지를 위해 제한된 수준에서 English 텍스트 혼용을 허용.
4. **접근성 (a11y)**:
   - 타이머, 포기하기, Pause/Resume, Skip 등 핵심 조작은 키보드만으로도 접근 가능해야 하며, 상태 변화는 스크린리더가 인지할 수 있는 텍스트로 함께 전달되어야 한다.
5. **보안 및 계정 보호 (Security)**:
   - 회원가입, 로그인, 동기화 구간은 암호화된 전송을 전제로 해야 하며, 비밀번호는 평문으로 저장할 수 없다. 인증 정보는 안전한 저장 방식과 만료 정책을 가져야 하고, 익명 KPI/동기화 식별자는 개인식별을 최소화하는 범위에서만 사용해야 한다.

## 5. UI/UX 상태 정책
- **Empty State (대시보드)**: 할 일 목록이 비었을 때 배경을 채우는 일러스트 및 안내 문구 노출.
- **Loading State**: 타이머 화면 전환 시 1초 이내 검은색 Dimmed 로딩 페이드 활용하여 시각적 구분을 제공.
- **Error State**: 인증 만료, 동기화 충돌, 네트워크 실패 발생 시 사용자가 현재 데이터 보존 여부와 다음 행동(재시도/로그인/최신 상태 반영)을 이해할 수 있는 안내 문구를 제공한다.
- **몰입 오버레이 (사이드바 통제)**: 집중 모드(데스크톱) 우측 사이드바에서는 팝업 및 작업 간섭을 금지하고 철저히 'Read Only'로 동작.

## 6. 제약 조건 & 리스크 (Constraints & Risks)
- **Local-First 및 오프라인-백엔드 동기화 (Hybrid Data Approach)**:
    - 기본적으로 앱의 **핵심 집중 루프 기능(Task 등록/수정, 집중 세션 시작/완료, 로컬 보상 및 통계 확인)**은 회원가입 없이 로컬 환경(브라우저 localStorage 및 IndexedDB)에서 단독 실행될 수 있어야 하며, 오프라인 환경에서도 원활 작동해야 한다.
    - 단, 데이터의 영구 보존 및 멀티 디바이스 확장을 위해 **회원가입/로그인 및 백엔드(Web Server, DB Server) 인프라를 필수 구축**한다. 유저가 로그인한 상태에서는 로컬 저장소의 데이터(과제, 집중 세션 사실값, 오늘의 나무/SP/레벨 집계, 사용자 설정)가 원격 DB로 즉시 동기화되거나 재시도 가능한 방식으로 반영되어야 한다.
    - KPI 계측은 위 핵심 루프와 별도로 동작해야 하며, 비로그인 상태의 익명 이벤트(`app_first_open` 등)도 제품 지표 산출에 필요한 범위 내에서 수집 가능해야 한다.
    - 오프라인 상태에서 발생한 KPI 이벤트는 로컬 큐에 임시 저장한 뒤 온라인 복귀 시 재전송할 수 있어야 하며, 비로그인 익명 이벤트와 로그인 이후 사용자 이벤트를 연결할 수 있는 최소 식별 규칙이 필요하다.
- **백그라운드 타이머 중단 리스크**: 모바일 웹브라우저 특성 상, 유저가 화면을 끄거나 다른 앱으로 넘어갈 경우 OS가 탭 자원을 회수할 수 있다.
  - **대응 방안**: 타이머 Start Timestamp를 localStorage에 보존하여 탭 갱신 시 오차를 교정한다.

## 7. Out of Scope (이번 배포/V1 범위 제외 항목)

MVP 핵심 가치(집중 루프 검증)를 타겟팅하므로, 확장형 복합 대시보드 시안(`_6`)에 속한 요소들은 **결정적으로 V2 배포판**으로 이관합니다.

1. **상점 / 소셜 / 챌린지 탭**: 시안 `_6/code.html` 좌측 네비게이션에 명시된 모든 네트워크형 시스템 (친구 랭킹, 커뮤니티 타임라인 피드, 챌린지 초대, 상점에서 항목 구입 등).
2. **나만의 숲 샌드박스**: 개별 나무를 좌표에 배치하거나 다른 유저들에게 보여주는 커스텀 숲 가꾸기.
3. **유료화 / 결제**: SP 재화나 프리미엄 혜택 업그레이드 기능 결제 파이프라인.
4. **연속 달성일수(Streak)**: 연속 접속/연속 완료 보상 체계 및 streak UI 노출은 V1 범위에서 제외한다.

## 8. 용어 정의 (Glossary)

도메인 혼란 방지를 위해 UI에 쓰이는 용어를 명확히 합니다.

| 용어 | 정의 / 문맥상 의미 | 비고 |
|---|---|---|
| **집중 모드 (Deep Focus)** | 타이머 카운트가 시작되어 불필요한 UI 요소(네비게이션 등)가 절제되고, 몰입 연출(Dimming, 글로우 이펙트 등)이 적용된 집중 전용 화면 상태. 전체 테마(라이트/다크)는 강제 변경되지 않음. | |
| **씨앗 포인트 (SP)** | 25분 집중 세션을 성공적으로 완료했을 때 얻는 앱 내 가상 재화. | 상점 사용처는 V2 구현 |
| **숲지기 (Level 명칭)** | 유저의 누적 SP 포인트에 기인한 계급 칭호 단계체계 (LV.24 등). | |
| **몰입 파기 (Give Up)** | 약속된 세션을 수행하지 못하고 강제로 타이머를 폐기/취소하여 0 초크가 되는 페널티 행위. | |
| **일시정지 (Pause)** | 화장실 등 긴급 행위를 위해 부득이 수 분간 타이머를 프리징하는 행위. | |
