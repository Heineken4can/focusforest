# 디자인 및 UI/UX 스탠다드 가이드라인 (UI)

이 문서는 서비스의 시각적 인터페이스 설계, 디자인 시스템 구축, 사용자 경험 최적화(UI-Plan, UI-Review, UI-Act)를 담당하는 디자이너 에이전트를 위한 핵심 가이드라인입니다.

---

## 0. AI 협업 및 프로젝트 특화 원칙 (Core Workflow)
실무 프로젝트 경험을 바탕으로, AI 파트너와 협업 시 아래 원칙을 최우선으로 적용합니다.

- **도메인 권한 엄수 (Cross-Domain Read-Only)**: 디자이너 에이전트(`ui-plan`, `ui-rv`, `ui-act`)는 디자인 전용 작업 폴더(`docs/02. ui/`) 및 스탠다드 로컬 파일(`.agents/standards/UI_GUIDE.md`) 내에서만 쓰기/수정 권한을 가집니다. 기술(FE/BE) 문서나 프론트엔드 코드, 일반 기획 문서(`PRD.md`)를 수정해야 할 경우, 절대 직접 덮어쓰지 않고 `docs/02. ui/` 하위에 수정 제안서 마크다운(.md) 파일(예: `docs/02. ui/fe_modification_request.md`)을 별도 작성한 뒤 유저에게 해당 파트의 에이전트를 호출하도록 가이드합니다.
- **경험 중심 테마 번역 (Experience-First)**: PO가 명세한 '코어 경험 테마'와 기획의 목적을 시각적으로 어떻게 풀어낼지 초기 컨셉을 확실히 정의하여 프로젝트 전 과정의 일관성을 유지합니다.
- **개발 구현 가능성 고려**: 화려하기만한 디자인보다는 최종적으로 프론트엔드가 구현(`Tailwind CSS`, 컴포넌트 시스템 등) 가능하며 재사용성을 높일 수 있는 디자인 시스템 및 토큰(Token) 설계를 최우선 목적으로 합니다.

---

## 1. 디자인 코어 원칙 (Design Principles)

- **시각적 계층 구조 (Visual Hierarchy)**: 사용자의 시선이 가장 중요한 액션(예: Primary 버튼, 핵심 폼)으로 자연스럽게 이동하도록 크기, 색상, 대비를 활용하여 중요도를 명확히 구분합니다.
- **일관성 (Consistency)**: 애플리케이션 전체에 걸쳐 동일한 디자인 토큰(Color, Typography, Spacing, Border Radius)을 적용하여 사용자 혼란을 방지합니다.
- **프로젝트 맞춤 테마 적용 (Theme Alignment)**: 명시된 기획(PRD) 문서의 도메인 성격에 맞춰 브랜드 정체성과 테마(예: 엔터프라이즈 B2B, 게이미피케이션 B2C 등)를 시각적으로 명확하게 번역하여 표현합니다.

---

## 2. 디자인 시스템 및 토큰 (Design System & Tokens)

### 2.1 색상 팔레트 (Color Palette)
- **Background**: 프로젝트 컨셉 문서(PRD)에 정의된 베이스, 표면(Surface) 컬러 구조를 바탕으로 앱 전체의 라이트/다크 배경색을 주조색으로 설정합니다.
- **Primary / Accent**: 브랜드를 상징하고 핵심 UI(버튼, 링크, 강조 영역)에 적용될 원색을 명확히 정의하여 상태 변화나 주요 액션을 직관적으로 강조합니다.
- **Text**: Contrast 비율(WCAG AA)을 준수합니다. 배경색과 강한 명도 대비를 갖도록 주요 텍스트(Primary Text) 및 보조 텍스트 색상을 체계화합니다.

### 2.2 타이포그래피 (Typography)
- **명시성**: 디스플레이용 폰트(숫자, 배너 타건 등)와 본문용 폰트(제목, 설명)를 구분하되 전체 폰트 패밀리 수는 2~3개 이하로 제한합니다.
- **스케일**: h1부터 본문(body), 캡션(caption)까지 체계적인 폰트 사이즈(rem 단위 기준) 계층을 정의하여 적용합니다.

### 2.3 간격 시스템 (Spacing & Layout)
- 4px 또는 8px 배수 시스템(Grid System)을 사용하여 요소 간 여백(Margin, Padding)의 일관성을 확보합니다.

---

## 3. 마이크로 인터랙션 및 UX
- **상태 피드백**: Hover, Active, Disabled, Loading 등 모든 상태에 대한 시각적 피드백을 위계에 맞게 반드시 정의합니다.
- **마이크로 인터랙션 명세**: 프로젝트 성격에 맞는 인터랙션(예: 상태 변화 알림, 모달 컴포넌트 등장 효과 등)의 부드러운 트랜지션 타이밍 및 애니메이션 스펙을 세밀하게 작성합니다.

---

## 4. 확장성 및 브라우징 (Accessibility & Responsive)
- **반응형 디자인 (Responsive)**: 데스크탑 뿐만 아니라 모바일/태블릿에서도 UI가 깨지지 않고 최적의 사용성을 제공하도록 Breakpoint별 레이아웃을 기획합니다.
- **명도 대비 (Contrast Ratio)**: WCAG 2.1 AA 기준 이상을 준수하여 주요 텍스트의 가독성을 보장합니다.

---

## 5. 역할별 특별 지침
### UI-Plan (디자인 설계자) 특별 지침
- 컴포넌트나 레이아웃을 설계할 때 단순한 "예쁜 화면"이 아닌, 유저가 목표를 달성하기 위한 방향(UX)을 문서(`design_system.md`, `ui_concept.md`)로 철저히 계획합니다.
- 기획서(PRD)의 요구사항과 Features를 모두 담을 수 있는 와이어프레임 구조를 마크다운 형태(비주얼 텍스트 또는 프롬프트 명세)로 정밀 묘사합니다.
- **타 역할 핸드오프(Handoff) 체크리스트**:
  - **to FE-Plan**: 완성된 디자인 토큰 세트, 페이지별 레이아웃의 마진/패딩 상세수치, 모바일/태블릿 상세 반응형(Breakpoint) 가이드, 에셋(이미지, 아이콘 규칙) 정보 전달.

### UI-Review (디자인 검수자) 특별 지침
#### 검수 중점 항목
다음 4개 영역을 절(節) 번호를 기준으로 검수한다.

| 영역                  | 참조 절 | 주요 체크포인트                                                                                     |
| --------------------- | ------- | --------------------------------------------------------------------------------------------------- |
| 도메인 권한 준수      | 0절     | 타 파트 문서(FE/BE/PO) 직접 수정 없이, 제안서(.md) 형태로 요청이 이루어졌는가                       |
| 디자인 코어 원칙      | 1절     | 시각적 계층(주요 액션으로 시선 유도) / 프로젝트 맞춤 테마 적용 / 토큰 일관성                        |
| 디자인 시스템 및 토큰 | 2절     | 색상 팔레트(Background·Primary·Text) 정의 / 폰트 패밀리 3개 이하·rem 스케일 / 4px·8px 간격 배수 |
| 마이크로 인터랙션     | 3절     | Hover·Active·Disabled·Loading 상태 피드백 정의 / 마이크로 인터랙션 테마 맞춤 타이밍 스펙         |
| 접근성 및 반응형      | 4절     | Breakpoint별 레이아웃(모바일·태블릿·데스크탑) / WCAG 2.1 AA 명도 대비(텍스트 4.5:1 이상)          |

#### 검수 결과 등급 기준
- **CRITICAL**: 디자인 원칙 위반 또는 WCAG 접근성 기준 미달. 즉시 수정 필요.
- **WARN**: 디자인 토큰 일관성 훼손 또는 명세 누락. 개선 권장.
- **INFO**: 완성도 향상을 위한 제안 사항.

#### 리포트 작성 형식 (`*_rv.md`)
```markdown
# UI 디자인 검수 리포트

| 항목 | 내용 |
|------|------|
| 검수 대상 | [파일명] |
| 검수 기준 | `.agents/standards/UI_GUIDE.md` |
| 검수자 | ui-rv2 |
| 검수일시 | [날짜] [시간]|
| 종합 판정 | PASS / FAIL |

## 1. [영역명] — 판정: PASS / FAIL
| ID | 등급 | 지적 사항 | 근거 (UI_GUIDE.md 절) |
|----|------|----------|----------------------|
| A-1 | WARN | [내용] | UI_GUIDE.md 2절 |

## 종합 지적 사항 요약
| ID | 등급 | 항목 | 조치 요약 |
|----|------|------|----------|

**CRITICAL: N건 / WARN: N건 / INFO: N건**
```

### UI-Act (디자인 생산자) 특별 지침

- 계획된 디자인 명세를 바탕으로 프론트엔드 개발자가 즉각적으로 사용할 수 있는 구체적인 가이드(`design_tokens.json`, `tailwindcss config`의 컬러 스펙, SVG 코드로 된 에셋)를 생산하여 `docs/02. ui/` 경로에 저장합니다.
- 필요 시 `generate_image` 툴을 활용하여 UI Mockup 레퍼런스 이미지를 생성한 뒤, 프론트엔드(`fe-act`) 작업자가 후속 구현을 즉시 시작할 수 있도록 파일 경로와 함께 명시적으로 전달(Handoff)합니다.
