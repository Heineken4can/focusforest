# Doc Normalizer (Korean) Skill

## 개요

설계 문서가 표준 포맷을 지키지 않으면 검수(rv) 사이클이 길어지고,
AI 툴이 문서를 잘못 읽을 위험이 높아집니다.
이 스킬은 문서를 일관된 포맷으로 정규화합니다.

## 이 스킬을 사용하는 시점

- 새 문서를 작성한 직후 포맷 점검
- 오래된 문서를 최신 표준에 맞게 업데이트할 때
- 여러 문서 간 용어/표현이 튈 때 정리
- 검수 전 자가 점검 시

## 1. 표준 문서 포맷 체크리스트

### 1.1 헤더 구조

```markdown
# [프로젝트명] [버전] — [파트명] ([파일명 약칭])

| 버전 | 날짜 | 작성자 | 변경 내용 |
|------|------|--------|-----------|
| v1.0 | YYYY-MM-DD | [역할] | [내용] |

## 참조 문서
- [문서명]: [경로]
```

```text
확인 항목:
□ 제목 헤더(H1)가 정해진 형식을 따르는가
□ 버전 이력 테이블이 있는가 (버전/날짜/작성자/변경내용 4개 컬럼)
□ 버전은 vX.X 형식인가
□ 날짜는 YYYY-MM-DD 형식인가
□ 참조 문서 섹션이 있는가
□ 참조 문서 경로가 실제로 존재하는 파일인가
```

### 1.2 섹션 구조

```text
확인 항목:
□ H2 이하 섹션이 번호로 구분되어 있는가 (1. 2. 3. ...)
□ 빈 섹션(내용 없이 제목만 있는 절)이 없는가
□ 문서 목적 섹션(§1)이 있는가
□ HR(---) 구분선이 주요 섹션 경계에 일관되게 사용되는가
```

### 1.3 표 포맷

```text
확인 항목:
□ 테이블 헤더와 구분선 행이 있는가
□ 빈 셀은 "—"로 표기하는가
□ 컬럼 수가 모든 행에서 일치하는가
```

### 1.4 코드 블록

```text
확인 항목:
□ 코드 블록에 언어 식별자가 있는가 (sql, mermaid, typescript 등)
□ SQL 예시에 닫는 세미콜론이 있는가
□ mermaid 다이어그램 문법 오류가 없는가
```

## 2. 용어 통일성 체크

| 비표준 표현 | 표준 표현 |
|------------|---------|
| 할일, 할 일, Todo | **Task** (화면 텍스트는 "할 일") |
| 포모도로 | **뽀모도로** (PRD 기준) |
| 포인트, 경험치, XP | **SP (Soul Point)** |
| 집중 세션, 포커스 세션 | **Focus Session** (코드) / **집중 세션** (문서 본문) |
| 나무, 트리 | **나무** (UI 텍스트) / **tree** (코드) |
| 이어하기, 재개 | **Resume** (코드) / **이어하기** (UI 텍스트) |
| 포기하기, 그만하기 | **Give Up** (코드) / **그만하기** (UI 텍스트) |
| streak, 연속 집중 | **streak** (코드) / **연속 달성일** (UI 텍스트) |
| UserSnapshot, ProgressSnapshot | **UserProgressSnapshot** |
| bootstrap, 부트스트랩 | **bootstrap** (코드) / **초기 동기화** (한글 설명) |

## 3. 정규화 실행 절차

### STEP 1: 문서 전수 스캔

```text
1. 대상 파일을 읽는다
2. §1.1 헤더 구조 확인
3. §1.2 섹션 구조 확인
4. §1.3 표 포맷 확인
5. §1.4 코드 블록 확인
6. §2 용어 통일성: grep으로 비표준 용어 탐색
```

### STEP 2: 이슈 목록 작성

```text
[위치] 라인 N: [현재 내용] -> [수정 제안]
예) 라인 3: 버전 이력 없음 -> 표준 버전 이력 테이블 추가 필요
예) 라인 47: "포모도로" -> "뽀모도로"
```

### STEP 3: 수정 적용

- 용어 오류: 즉시 수정
- 포맷 누락: 표준 템플릿으로 채움
- 참조 경로 오류: 실제 파일 경로로 수정
- 섹션 구조 개편이 큰 경우: 변경 범위를 사용자에게 알리고 진행

### STEP 4: 리포트 출력

```markdown
## Doc Normalizer 결과

대상 파일: [파일명]
검사 시각: YYYY-MM-DD HH:mm

| 항목 | 결과 | 비고 |
|------|------|------|
| 헤더 구조 | OK / WARN / FAIL | |
| 섹션 구조 | OK / WARN / FAIL | |
| 표 포맷 | OK / WARN / FAIL | |
| 코드 블록 | OK / WARN / FAIL | |
| 용어 통일 | OK / WARN / FAIL | [N건 수정] |

수정 완료: N건 / 사용자 확인 필요: N건
```
